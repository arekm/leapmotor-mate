# Mate 4.18.0 — Each car has its own operation PIN

The PIN typed in Settings → Vehicle is the one commands use, and the diagnostics bundle shows the fan and
temperature range the cloud gives each car.

---

## What changes

### Each car has its own operation PIN ([#449](https://github.com/ProtossBlaster/leapmotor-mate/pull/449), @arekm)

On a single car, changing the PIN in Settings → Vehicle did not change the PIN commands use. Mate stored
the PIN in two places: an install-wide PIN, which the Settings form wrote on one car, and a PIN per car,
which the setup wizard has written for every car since multi-car setup and which both readers rank first.
A new PIN typed in Settings went to the one commands did not read.

The PIN is set on the car, and the cloud checks it per VIN. Mate now keeps only a PIN per car:

- Settings → Vehicle reads "Operation PIN of this car", with the car's model and the end of its VIN.
  With two cars, "Which car" lists only the cars, with the car on screen selected; "All cars (one PIN)"
  is gone.
- The setup wizard labels the PIN "Operation PIN (set on the car)", and with two cars "Operation PIN of
  this car" under each car. It submits only the cars its last detection found: a retry that failed, or an
  email edited after a detection, no longer finishes setup with the cars found before.
- With no car detected, the wizard says the PIN is not saved, and to set it in Settings → Vehicle once
  Mate has found the car.
- A command from the page to a car with no PIN is not sent: "✗ No operation PIN for C10 ·123456: set it
  in Settings → Vehicle". From Home Assistant it is not sent either, and the log says
  "MQTT: command lock failed: Vehicle PIN is missing".
- The Ready automation (preheat or windows when the car turns on) uses the PIN of the car that turned on,
  not the one an earlier command left in the session.
- Logout clears every car's PIN.
- `LEAPMOTOR_PIN`, for an install configured from its environment, is the PIN of every car without its own.

The manuals (EN, DE, ES, FR, IT) call the PIN the car's, set on the car.

### A car's function config is kept, and the bundle shows it ([#446](https://github.com/ProtossBlaster/leapmotor-mate/pull/446), @arekm)

The cloud's vehicle list gives each car a function config (`funcConfig`) with the fan's and the
temperature's range for remote climate. Mate read the list but did not keep that field. It is now kept
with the rest of the car's list entry, and the diagnostics bundle prints it after the account's rights:

```
funcConfig: {"HVAC": {"fan": {"max": "9", "min": "1", "unit": "gear"}, "temperature": {"max": "32", "min": "18", "unit": "celsius"}}, "valid": true}
```

or `null` when the list has none. No page, setting or command changes: the fan stays 1 to 7.

## Upgrade impact

- When the database opens, and again once the cars are registered, an install-wide PIN from an earlier
  version becomes the own PIN of every car that has none. On a single car it also replaces the car's own
  PIN, so an install with this bug is fixed without retyping. With two cars a car's own PIN is never
  overwritten. The install-wide PIN is then cleared.
- An install whose car list still holds a car of an earlier account, after an account switch, counts as
  two cars: the current car keeps its own PIN, and the install-wide PIN goes to the other car. Measured:
  current car `1111` from the wizard, install-wide `2222` typed later in Settings; after the migration the
  current car reads `1111`. If a command is refused for a wrong PIN after the update, type the PIN once
  more in Settings → Vehicle: the form opens on the car on screen.
- A command to a car with no PIN was sent with the PIN the session had; now it is not sent.
- No schema change. In the eight languages one label is added and the PIN hint is changed; the setup
  wizard's PIN labels and its note are in its own page.

- Locally, in Docker: 5,790 passed, 2 skipped (Node.js installed for the wizard's own script).

Every page answers 200 with no error in the page, and Settings → Vehicle read "Operation PIN of this car" with the car's VIN in the form. The only errors in its log are the home MQTT broker refusing connections, as on 4.17.0. No command was sent to the car.

## Italiano

# Mate 4.18.0 — Ogni auto ha il suo PIN operativo

Il PIN scritto in Impostazioni → Veicolo è quello che usano i comandi, e il pacchetto di diagnostica mostra
l'intervallo della ventola e della temperatura che il cloud dà a ogni auto.

## Cosa cambia

### Ogni auto ha il suo PIN operativo ([#449](https://github.com/ProtossBlaster/leapmotor-mate/pull/449), @arekm)

Con una sola auto, cambiare il PIN in Impostazioni → Veicolo non cambiava il PIN usato dai comandi. Mate
teneva il PIN in due posti: un PIN dell'installazione, che il modulo delle Impostazioni scriveva con una
sola auto, e un PIN per auto, che la configurazione iniziale scrive per ogni auto da quando esistono più
auto e che entrambi i lettori mettono per primo. Il PIN nuovo scritto in Impostazioni finiva in quello che
i comandi non leggevano.

Il PIN si imposta sull'auto, e il cloud lo controlla per VIN. Ora Mate tiene solo un PIN per auto:

- Impostazioni → Veicolo dice «PIN operativo di questa auto», con il modello e la fine del VIN. Con due
  auto, «Per quale auto» elenca solo le auto, con selezionata quella a schermo; «Tutte le auto (un solo
  PIN)» non c'è più.
- La configurazione iniziale chiama il PIN «PIN operativo (impostato sull'auto)», e con due auto «PIN
  operativo di questa auto» sotto ogni auto. Invia solo le auto trovate dall'ultimo rilevamento: un nuovo
  tentativo fallito, o un'email modificata dopo un rilevamento, non chiudono più la configurazione con le
  auto trovate prima.
- Senza un'auto rilevata, la configurazione dice che il PIN non viene salvato e di impostarlo in
  Impostazioni → Veicolo quando Mate avrà trovato l'auto.
- Un comando dalla pagina a un'auto senza PIN non parte: «✗ No operation PIN for C10 ·123456: set it in
  Settings → Vehicle». Da Home Assistant non parte nemmeno, e il log dice «MQTT: command lock failed:
  Vehicle PIN is missing».
- L'automazione all'accensione (preriscaldamento o finestrini quando l'auto si accende) usa il PIN
  dell'auto che si è accesa, non quello lasciato nella sessione da un comando precedente.
- Il logout cancella il PIN di ogni auto.
- `LEAPMOTOR_PIN`, per un'installazione configurata dall'ambiente, è il PIN di ogni auto senza il suo.

I manuali (EN, DE, ES, FR, IT) chiamano il PIN quello dell'auto, impostato sull'auto.

### La configurazione delle funzioni dell'auto viene tenuta, e il pacchetto la mostra ([#446](https://github.com/ProtossBlaster/leapmotor-mate/pull/446), @arekm)

L'elenco dei veicoli del cloud dà a ogni auto una configurazione delle funzioni (`funcConfig`) con
l'intervallo della ventola e della temperatura del clima da remoto. Mate leggeva l'elenco ma non teneva
quel campo. Ora lo tiene con il resto della voce dell'auto, e il pacchetto di diagnostica lo stampa dopo i
diritti dell'account:

```
funcConfig: {"HVAC": {"fan": {"max": "9", "min": "1", "unit": "gear"}, "temperature": {"max": "32", "min": "18", "unit": "celsius"}}, "valid": true}
```

oppure `null` quando l'elenco non lo porta. Nessuna pagina, impostazione o comando cambia: la ventola resta
da 1 a 7.

## Impatto dell'aggiornamento

- Quando si apre il database, e di nuovo quando le auto sono registrate, un PIN dell'installazione di una
  versione precedente diventa il PIN di ogni auto che non ne ha uno. Con una sola auto sostituisce anche il
  PIN dell'auto, quindi un'installazione con questo difetto si sistema senza riscriverlo. Con due auto il
  PIN di un'auto non viene mai sovrascritto. Poi il PIN dell'installazione viene svuotato.
- Un'installazione il cui elenco di auto tiene ancora un'auto di un account precedente, dopo un cambio di
  account, conta come due auto: l'auto attuale tiene il suo PIN, e il PIN dell'installazione va all'altra.
  Misurato: auto attuale `1111` dalla configurazione iniziale, PIN dell'installazione `2222` scritto dopo
  in Impostazioni; dopo la migrazione l'auto attuale legge `1111`. Se dopo l'aggiornamento un comando viene
  rifiutato per PIN sbagliato, riscrivi il PIN una volta in Impostazioni → Veicolo: il modulo si apre
  sull'auto a schermo.
- Un comando a un'auto senza PIN partiva con il PIN che aveva la sessione; ora non parte.
- Nessuna modifica dello schema. Nelle otto lingue un'etichetta è aggiunta e il suggerimento sul PIN è
  cambiato; le etichette del PIN e la nota della configurazione iniziale sono nella sua pagina.
